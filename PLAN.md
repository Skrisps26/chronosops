# ChronosOps: local-first, Bedrock-powered incident intelligence

## Context
Build an incident-intelligence platform for all three Graph Hacks tracks with a real, controlled outage as its centerpiece: monitor a dedicated EC2-hosted demo service, ingest a live dedicated Slack channel, reason over FalkorDB evidence, request approval, perform a bounded recovery and verify restored health. ChronosOps and FalkorDB stay on the user's machine with Docker Compose and an HTTPS tunnel; AWS Bedrock supplies every LLM and embedding call. A single disposable EC2 workload is explicitly selected for demonstration, never for hosting FalkorDB; retain the original synthetic cost-constrained failover scenario as a separately labeled simulation. Deliver `agents.md`, implementation, tests, reproducible setup, measured evaluation, demo recording and publishable blog; the repository was empty when inspected.

## Evidence and refinements
1. Lead with one incident story, not three disconnected applications: “Who owns payments and why? What breaks? Which failover is permitted? What did the last session learn?” Every answer/action carries its actual graph evidence.
2. Separate *blast radius* from centrality. `A DEPENDS_ON B` means failure of B affects A: traverse incoming dependencies. Harmonic centrality has approximate reachable counts; use distinct bounded traversal for exact fixture impact, and label the bound in the UI.
3. Separate authoritative operational topology from extracted company knowledge. GraphRAG's current ontology API is `Ontology`, `Entity`, `Relation`, `Attribute`; README examples still contain older names. Its extracted semantic edges are `RELATES {rel_type}`, not native domain edge types. Pin and probe the actual release before implementing queries.
4. Trusted paths include source/health ingestion, approved real action records, simulation TrafficState, memory and traces. SSM execution is separate from graph writes, allowlisted and human-approved. Models never receive writer credentials or arbitrary AWS tools.
5. Enforce DB ACLs, server-owned tenant identity and scoped AWS recovery credentials. Shared company/topology data is demo-only; memory and authorization to operate the real instance remain tenant-isolated.
6. GraphRAG already supports Bedrock through its official LiteLLM adapters. Do not invent Bedrock SDK classes or install a second vector database. Use the same Bedrock embedding model for ingestion and questions.
7. Cloudflare Quick Tunnels do not support SSE. Use WebSockets end-to-end and verify the public connection. The local machine must remain awake; a recording and clean-clone setup are mandatory backup deliverables.
8. Do not call live LLM evaluation deterministic. Fix fixtures and scoring, separate graph-only regression checks from live generation, and publish raw misses and measured latency. Compare equal models/corpus/context budgets without promising the graph wins.
9. Local Docker on existing hardware has no additional hosting subscription, and is the user's selected cheapest deployment. Railway was verified as a viable alternative with $5 trial credit and $1/month free credit, not unlimited free uptime (https://docs.railway.com/pricing/free-trial and https://docs.railway.com/pricing/plans). FalkorDB Cloud Free offers 100 MB but no TLS, persistence or backups (https://docs.falkordb.com/cloud/tiers/free). Neither alternative is selected; Bedrock inference remains separately metered.

- React/Vite/TypeScript, Cytoscape.js, native WebSocket client. Build static UI into the API image; use one application origin.
- Compose services: `db`, `app`, `proxy`; optional `tunnel` profile plus one-shot `seed` and `verify` profiles. `app` contains pinned Node runtime and official MCP server package; spawn separate read-only/writer stdio sessions through the official Python MCP client, not an HTTP MCP service exposed publicly. Use per-tenant sessions/credentials for acme and globex so database ACLs independently restrict private memory. Ingestion uses an additional privileged official Python client connection, unavailable to agents.
- Graphs: `company_brain`, `ops_topology`, `agent_memory_acme`, `agent_memory_globex`. Cross-graph joins use canonical IDs. Keep the 45-service/12-person/4-team/16-document synthetic fixture, and attach real EC2 deployment, timestamped health observations and Slack evidence with explicit `origin` values `synthetic`, `aws`, `probe`, `slack`. Only acme owns the real demo deployment and Slack connector; globex isolation tests cannot invoke its recovery. Never represent synthetic dependent nodes as observed outages.
- Local FalkorDB named volume mounted to the actual image data directory (docs currently show `/var/lib/falkordb/data`), AOF enabled with every-second sync. Configure ACL file and query timeouts at startup, not only runtime. Publish DB and Browser ports to loopback only, and never tunnel them. App is reachable externally only through the proxy.
- Nginx existing basic-auth support provides two demo identities mapped by trusted upstream header to acme/globex. Strip incoming identity headers and overwrite them from authenticated identity. App port remains private to Compose. Generate password hashes using an existing htpasswd tool; secret files are ignored. Do not build a login service. Public demos use HTTPS tunnel; loopback development may use HTTP. Keep browser Origin validation on state-changing endpoints and WebSocket handshake; tunnel script sets exact allowed public origin.
- Bedrock defaults: `AWS_REGION=us-east-1`, `BEDROCK_LLM_MODEL_ID=us.amazon.nova-lite-v1:0`, `BEDROCK_EMBED_MODEL_ID=amazon.titan-embed-text-v2:0`, `EMBEDDING_DIMENSION=256`, `LLM_MAX_TOKENS=1024`, extraction max tokens 2048, temperature 0. Use AWS_REGION_NAME for LiteLLM and region_name for ChatBedrockConverse. Verify account access in Module 0. Use on-demand inference only; no Bedrock Knowledge Bases, managed vector service, provisioned throughput or hosted agent runtime.
- Credentials: existing temporary/profile credential chain with read-only config mounts, never embedded secrets. AWS MCP performs development-time AWS discovery/provisioning of only the dedicated demo stack. Separate operator provisioning/fault-injection identity from runtime recovery identity. Runtime Bedrock permission is model-scoped; recovery permission is restricted to one instance and one pinned, parameterless restart SSM document. Agents see typed domain tools, not AWS administrator tools or arbitrary Run Command.

- Additional local Compose services: prometheus, blackbox, alertmanager, slack-connector; operator-only profile `operator` for provisioning/fault scripts. ## Approach: ordered module gates
Every module depends on the previous gate. Do not fan out implementation across gates. Tests plus an actual exercised path must pass before the next module starts. Record commands/results in `docs/PROGRESS.md`, API/version/fallback evidence in `docs/DECISIONS.md`, then commit/merge/push. Run current cumulative tests at each gate; do not repin incidental LLM wording. The existing libraries provide the infrastructure; new modules below are only application schemas, queries, prompts and adapters because no application code exists.

### Module 1 — Seed a reproducible incident and evidence corpus
Create `seed/generate.py`, `seed/load.py`, `seed/data/`, `seed/manifest.json`. Use `random` seed 42, NetworkX for a 45-service bounded sparse directed topology, Faker seeded for 12 people/4 teams, then insert the following deterministic scenario. Do not let filler edges change scenario impact or routes; filler components have no paths into `payments-primary`.

Canonical services include `gateway`, `checkout`, `orders`, `worker`, `payments-primary`, `payments-backup`, `premium`, `queue`. `DEPENDS_ON`: gateway→checkout, checkout→payments-primary, orders→payments-primary, worker→orders. Failure of payments-primary therefore affects exactly gateway, checkout, orders and worker within depth 5 (exclude failed root from affected count). Add normal current routing to the failed primary separately from candidate backup edges.

Backup `ROUTES_TO` edges, each with integer latency_ms/cost: checkout→premium (1,10), premium→payments-backup (1,10), checkout→queue (2,4), queue→payments-backup (3,4). With cap 12, the fastest route has latency 2 and cost 20 and is rejected; the safe route has latency 5 and cost 8. Store health for nodes/edges; no route may traverse the failed primary. Candidate routing and dependencies are different relationships.

Company sources: 4 RFCs, 4 Slack-style threads, 4 tickets, 4 PR/commit records; stable `document_id`, path, hash, service/person IDs in source text/front matter. `rfc-payments-failover` says queue failover was selected for bounded cost; Alice is the sole authored/resolved contributor to payments-primary and Payments owns it. Aliases `Payments API` and `pay-api` resolve to payments-primary using a seeded canonical mapping. Include deliberately irrelevant documents and one conflicting superseded rationale, marked with source version, for honest retrieval evaluation. Do not fabricate real organizations or source links.

Load operational topology via parameterized UNWIND batches of at most 300 with stable-ID MERGE. `Meta` is scoped per graph, with `ready=false` before load and `ready=true,hash=<manifest hash>` only after all expected counts/relationships validate. On failure leave unready; readiness endpoints must not serve partial data. Re-running same seed preserves counts and identifiers. Company structured files are prepared here and ingested by SDK in Module 3, not duplicated as an incompatible graph schema.

Gate: exact manifest counts; twice-loaded counts unchanged; deliberately interrupted load remains unready; independent NetworkX ancestor traversal produces the four affected service IDs.

### Module 2 — Query tools with actual graph evidence
Create `agents/tools.py`, `agents/queries.py`, `agents/schemas.py`, `mcp/client.py`. Define typed async domain functions `blast_radius(service_id: str)`, `choke_points()`, `failover_routes(source: str, target: str, max_cost: int)`, `who_owns(service_id: str)`, `bus_factor(service_id: str)`, `decision_provenance(service_id: str)`. Tenant is a bound server context, not a model argument. Knowledge tools initially use the ontology/schema contract completed in Module 3; do not expose them until corpus-ready, returning `NOT_READY` rather than fake data.

Every result has `data`, `evidence` (nodes/edges/source identifiers), `trace` (tool, graph, actual Cypher, redacted params, duration_ms, algorithm result), and `bounds` (depth/limit/truncated). Unknown identifiers → `NOT_FOUND`; no evidence → `EVIDENCE_INSUFFICIENT`; no safe path → `NO_SAFE_ROUTE`; timeout → `QUERY_TIMEOUT`. These are distinct outcomes. Pydantic rejects invalid cost, IDs and oversized questions before queries. Strings stay params; labels/edge types/limits are static code.

Blast radius query anchor: `MATCH (dependent:Service)-[:DEPENDS_ON*1..5]->(failed:Service {service_id:$service_id}) RETURN DISTINCT dependent.service_id` with literal `LIMIT 100`. Retrieve witness paths separately bounded to 100; avoid calling a path-limit count exact if truncated. Query a depth-6 frontier to flag the scope bound, not to silently claim unlimited reachability.

Failover uses `CALL algo.SPpaths({sourceNode:s,targetNode:t,relTypes:['ROUTES_TO'],weightProp:'latency_ms',costProp:'cost',maxLen:5,relDirection:'outgoing',pathCount:5}) YIELD path,pathWeight,pathCost` first, then with `maxCost:$max_cost`. Validate returned node/edge health and current blocked-route memory before proposal. A filtered limited set is not proof that no route exists: report “no eligible route found within search bounds.” If the selected build lacks maxCost but has SPpaths, enumerate bounded paths with `pathCount:5`, sum/filter costs in glue and explicitly expose search incompleteness. If SPpaths itself is missing, choose a stable image containing the documented API; do not write a shortest-path algorithm.

Choke points: `algo.betweenness({nodeLabels:['Service'],relationshipTypes:['DEPENDS_ON'],samplingSize:32,samplingSeed:42}) YIELD node,score`; label sampled. If unavailable, use `algo.pageRank('Service','DEPENDS_ON')`, labeled PageRank, not betweenness. Harmonic probe is recorded but not required for impact. Optional WCC/CDLP are not part of the demo.

Gate: exact route numbers and impacted IDs; injection payload remains data; real MCP reader cannot write even using `query_graph` with readOnly=false; tenant ACL cannot query the other private graph; unknown/unready/timeouts are not rendered as safety.

### Module 3 — Company Brain with stable identity and versioned citations
Create `agents/knowledge.py`, `seed/ontology.py`, `seed/ingest.py`. Use `GraphRAG(connection=ConnectionConfig(...,graph_name='company_brain'), llm=LiteLLM(model='bedrock/'+BEDROCK_LLM_MODEL_ID,max_tokens=2048,temperature=0,aws_region_name=AWS_REGION), embedder=LiteLLMEmbedder(model='bedrock/'+BEDROCK_EMBED_MODEL_ID,dimensions=256,normalize=True,aws_region_name=AWS_REGION), embedding_dimension=256, ontology=ontology, enable_cypher=False)`. Keep extraction/finalize serial for this small corpus to limit spend and avoid shared-entity update races.

Use current `Ontology`, `Entity`, `Relation`, `Attribute`, `TableMapping`, `Column` constructors from the pinned source, not deprecated README aliases. Entity declarations: Person, Team, Service, Decision, Ticket, PullRequest, SlackThread; SDK Document/Chunk remain SDK-managed. Relations: Person MEMBER_OF Team; Team OWNS Service; Person AUTHORED Decision/Ticket/PullRequest/SlackThread; Person RESOLVED Ticket; Decision ABOUT Service; Decision REFERENCES Document only if SDK reserved-label pattern permits it—otherwise keep provenance exclusively via source_chunk_ids/MENTIONED_IN rather than inventing an unsupported semantic Document entity. Add service/person stable attributes and ingest structured canonical CSVs keyed by service_id/person_id with `strict_mapping=True` before unstructured files. Use entity_key as the SDK authority and maintain explicit app mapping from that key to service_id; never authorize using name-derived SDK id.

Call `ingest(source=path,document_id=stable_id)` for each source; `finalize(resolve=True,judge=True,judge_vote=True)` once for the batch with the Bedrock LLM. Apply explicit canonical alias mapping after SDK resolution; ambiguous or conflicting canonical IDs fail ingestion and do not publish readiness. Do not hand-roll fuzzy entity resolution. Ensure aliases lead to one actionable canonical entity while retaining source provenance.

`who_owns`, contributor aggregation and decision provenance query `RELATES` filtered by `rel_type`, and SDK entity/key properties verified by the probe. Bus factor is a documented *knowledge concentration proxy*: count distinct authors/resolvers of documents/tickets about that service, flag count <=1; zero means “no recorded contributors,” not proof nobody owns it. Return count, contributing identities and citations.

Router: a single resolved service with descriptive lookup uses chunk vector retrieval; ownership, why/provenance, multiple entities and temporal questions use typed graph tools plus SDK `retrieve()` for supporting passages. Unknown/ambiguous entity produces abstention/clarification, not guessed identity. Vector-only query uses the same 256-dimension Chunk index and returns top 5 chunks without relation expansion; use the pinned SDK vector store/query procedure, not text-to-Cypher.

Resolve exact citations through `Document-[:PART_OF]->Chunk` and `MENTIONED_IN`/RELATES.source_chunk_ids. API citation fields: document_id, path, content_hash, chunk_id, chunk_index, excerpt. Let the model cite only numbered supplied evidence IDs; reject nonexistent citations. Empty evidence returns EVIDENCE_INSUFFICIENT. Do not assume default MultiPath metadata always contains chunk IDs. SDK retrieval is trusted library execution, but public operational agent tools still go through MCP; disclose that SDK ingestion/retrieval uses its native client.

Single-file update: `rag.update(source=path,document_id=stable_id)` then finalize once. Editing `rfc-payments-failover` from “bounded cost” to “rollback speed under the same cost cap” must replace the cited rationale and source hash without duplicating entities. Keep operations serialized during update; company readiness is false until completed, and failure shows unavailable rather than stale fresh-labeled knowledge. Restore fixture through the same update path after the test.

Gate: ownership and rationale cite the right source/chunk; alias questions resolve same service ID; single contributor flag appears; update changes answer evidence and hash; unrelated/shared entities remain; a nonexistent source ID cannot be emitted as a valid citation.
