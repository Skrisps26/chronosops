# Verified integration decisions

## Module 0

- ChronosOps/FalkorDB run locally. A single disposable EC2 workload is reserved for a later module; no EC2 resource has been created.
- GitHub repository created at https://github.com/Skrisps26/chronosops. The approved plan and agent instructions were committed and pushed to main before starting feat/module-0.
- Docker is not installed. Rootless Podman is installed and reports rootless=true; no Compose provider was initially present. Use the same Compose specification through a pinned Podman Compose provider instead of requiring a privileged Docker installation. This is a local runtime adaptation, not a hosting change.
- Existing AWS MCP configuration was discovered in the user's Codex configuration. The named `sai` AWS profile uses AWS CLI login credentials. Its expired session was renewed with explicit user permission; no credentials were copied into the repository.
- AWS MCP actually executed STS GetCallerIdentity through `aws___run_script`; structured result recorded api_calls status=success. Raw evidence is in ignored artifacts/aws-mcp.json. Public tool discovery alone does not prove authenticated API access.
- Bedrock ListFoundationModels and ListInferenceProfiles were executed through the same AWS MCP server in us-east-1. Nova Lite (`us.amazon.nova-lite-v1:0`) and Titan Text Embeddings V2 (`amazon.titan-embed-text-v2:0`) were ACTIVE. This proves catalog availability, not invocation permission or model output quality.
- mcp-proxy-for-aws 1.7.0's optional metadata injection caused `LocalProtocolError: Too much data for declared Content-Length` in the direct official client. The official signed library connection without optional metadata succeeded. Specify region explicitly in every run_script API call; do not hand-roll signing, suppress auth errors or patch vendor packages. Existing user-wide MCP configuration was not modified.
- Bootstrap scripts must fail closed when model/API/SDK contracts are unavailable. Modules 1 onward remain gated by Module 0 live verification; recorded data is not a replacement for a successful live probe.
- Published GraphRAG-SDK 1.4.0 does not expose the planned constructor's enable_cypher setting. The official repository commit `35e67a0b27fdcc7f2c28508b09e86169851a8187` does: `enable_cypher: bool = False` in api/main.py, forwarded to MultiPathRetrieval. Pin the official source commit as allowed by Module 0 rather than mixing incompatible legacy examples or fabricating a parameter. Runtime ingestion/update/citation behavior remains subject to the actual probe.
- Local FalkorDB image built successfully through rootless Podman. Actual authenticated PING returned PONG; a probe-owned node was written, read through GRAPH.RO_QUERY with value1 and then deleted. No demonstration graph was touched.

## Correctness repair: deployment safety

- Recovery permissions follow the plan's explicitly named operations, not inferred SDK calls. The IAM skill's Service Authorization Reference path applies; Autopilot source-code policy generation was not used. SSM `SendCommand` requires the document and instance resource types; both are restricted to this stack. `GetDocument` is document-scoped. `GetCommandInvocation`, `DescribeInstanceInformation`, and EC2 `DescribeInstances` have no resource-level scope. References: https://docs.aws.amazon.com/service-authorization/latest/reference/list_ssm.html and https://docs.aws.amazon.com/service-authorization/latest/reference/list_ec2.html.
- Runtime recovery requires a separate existing `AWS_RECOVERY_PROFILE` and checks STS assumed-role identity against the published deployment's role. The operator/generation profile is not a fallback. No runtime credential identity or deployed IAM policy has yet been verified.
- Preflight resolves and inspects the Amazon ARM64 AMI, then supplies that exact ID and its root-volume minimum to CloudFormation. This avoids a rolling SSM parameter changing the image after inspection. Standard CPU credits avoid surplus-credit charges. Current public Price List API rates, SKU and effective date replace hard-coded cost claims; an unavailable/ambiguous catalog result fails preflight.
- A deployment binding is published only after current AWS stack/instance ownership, expiry, encrypted volume, standard credits, online SSM agent and exact parameterless recovery document checks. Recovery submissions pin numeric document version and SHA-256 content hash. Previous bindings remain historical but inactive.
- `cfn-lint` 1.57.2 caught the incorrect CloudFormation spelling `CpuCredits`; the required property is `CPUCredits`. The corrected template passed validation with exit0. Reference: https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-properties-ec2-instance-creditspecification.html.
- Current account gate: after explicitly authorized renewal of profile `sai`, the official AWS MCP signed connection successfully executed STS GetCallerIdentity. CloudFormation DescribeStacks for `chronosops-demo` in `us-east-1` was explicitly denied by an organization service-control policy. Evidence: ignored `artifacts/aws-step3-discovery.json`. No retry, region change, workload mutation or policy bypass was attempted. Live deployment/IAM proof remains blocked, not passed.

## Correctness repair: probe evidence

- Prometheus raw range-vector timestamps are the scrape clock; instant query evaluation timestamps are not freshness proof. The client separately reads `timestamp(probe_success)` and requires agreement using absolute tolerance with `rel_tol=0`. Relative tolerance on epoch seconds otherwise accepted a one-second disagreement. References: https://prometheus.io/docs/prometheus/latest/querying/basics/ and https://prometheus.io/docs/prometheus/latest/querying/functions/#timestamp.
- Probe observations are immutable stable identities derived from deployment, endpoint and scrape timestamp. Changed values under the same identity fail closed. Bounded HealthObservation writes preserve actual exporter/probe/HTTP evidence and incident links.
- Prometheus3.15.0 release was discovered at https://github.com/prometheus/prometheus/releases/tag/v3.15.0. Docker Hub pull timed out; the documented official Quay alternative succeeded. Tested image: `quay.io/prometheus/prometheus@sha256:86b17a25c2db1d16a61b16b3c8f336679eb19e26333d03e808da387206e40faa`. `promtool check config` validated the configuration and both rules. Missing generated file-SD target produced the expected warning before publication, not a fallback target.
- Alertmanager reads a generated token file rather than a committed fallback token. Unknown exporter/scrape evidence is separate from workload failure; neither monitoring loss nor restoration creates an application incident. Resolved workload alerts without agent proof remain external recovery.

## Correctness repair: canonical source publication

- Pinned SDK tables sign application properties. Company queries use `services__service_id`, `people__person_id` and `teams__team_id`; `entity_key` and generated node IDs are SDK reconciliation state, not authorization identities. Supported table links point from Service to Team, so ownership is explicitly `RELATES {rel_type:'OWNED_BY'}` rather than reversed `OWNS`. Reference: https://github.com/FalkorDB/GraphRAG-SDK/blob/35e67a0b27fdcc7f2c28508b09e86169851a8187/graphrag_sdk/src/graphrag_sdk/core/tables.py.
- SourceRecord/Contribution/SourceRequest are application-owned records, separate from SDK metadata. PyYAML 6.0.3 parses existing front matter. Source versions remain unavailable until SDK update/delete and `finalize(resolve=True, judge=True, judge_vote=True)` finish, and the worker publishes the same revision. Exact SDK chunk IDs and indices drive citations. Reference: https://github.com/FalkorDB/GraphRAG-SDK/blob/35e67a0b27fdcc7f2c28508b09e86169851a8187/graphrag_sdk/src/graphrag_sdk/api/main.py.
- One local worker holds a non-expiring OS file lock. All writer entry points must share that file; independent container filesystems do not share this guarantee. The API performs no SDK writes. A crash leaves work durable for the next exclusive worker; no TTL permits an overlapping SDK writer.
- Initial ingestion uses one SDK session and one finalization after all canonical tables and documents, as the SDK documents. Individual source updates finalize before publication. Canonical CSV tables also receive application publication records because their row chunks are the actual supporting sources for structured ownership; ordinary document updates cannot replace those tables.
- The live SDK probe found additional unkeyed extracted Team nodes. Domain ownership/membership projections therefore require canonical signed identities and consistency with the structured owner/team fields; they do not treat every extracted relation as authoritative ownership.
- Default tests remain on an internal network. `docker-compose.bedrock-test.yml` explicitly adds runner egress, read-only AWS mounts and a private tmpfs login cache. A read-only login cache cannot refresh: botocore raised `Read-only file system` before signing. Its supported `AWS_LOGIN_CACHE_DIRECTORY` override permits refresh without modifying the host mount. Verified generation and Titan output: 256 dimensions, squared norm 1.0. Reference: https://github.com/boto/botocore/blob/develop/botocore/utils.py (`get_login_token_cache_directory`); the installed pinned botocore is 1.43.114.
- A separate operator smoke exposed `ImportError: libgomp.so.1` from installed hnswlib 0.8.0. The pinned SDK catches that import error and later logs a resolver failure while returning zero merges; a green ingestion return alone is therefore insufficient proof. The runtime now installs `libgomp1` and requires hnswlib directly before SDK work. Native nearest-neighbor execution and actual SDK provenance are separate gate checks. Sources: https://github.com/FalkorDB/GraphRAG-SDK/blob/35e67a0b27fdcc7f2c28508b09e86169851a8187/graphrag_sdk/src/graphrag_sdk/ingestion/resolution_strategies/llm_verified_resolution.py and https://github.com/FalkorDB/GraphRAG-SDK/blob/35e67a0b27fdcc7f2c28508b09e86169851a8187/graphrag_sdk/src/graphrag_sdk/storage/deduplicator.py.
- The first dependency fix exposed a second failure: the mounted host uv cache supplied an hnswlib wheel requiring GLIBC_2.43, while the pinned Debian container supplies GLIBC_2.41. A matching compiler stage installs the other locked dependencies first, then installs hnswlib through a container-specific cache; neither host-native hnswlib wheels nor compiler tools enter the runtime. Both installs use the same frozen lock. `HNSWLIB_NO_NATIVE=1` avoids host-CPU-specific instructions in its built wheel. Upstream build flag: https://github.com/nmslib/hnswlib/blob/v0.8.0/setup.py.

## Correctness repair: Slack lifecycle and notifications

- Slack Bolt 1.27.0 and Slack SDK 3.45.0 remain the pinned official transport. This source process exposes no Slack HTTP endpoint; its `AsyncApp` disables only HTTP signature middleware while Socket Mode authenticates through the app token and the bot workspace is checked with `auth.test`. The pinned SDK otherwise raises `signing_secret must not be empty` before a socket can start. No placeholder signing secret or custom authentication was introduced. References: https://docs.slack.dev/tools/bolt-python/concepts/socket-mode/ and the installed `AsyncApp.request_verification_enabled` HTTP-mode API.
- Native `AsyncSlackResponse` is dict-like but is not a `Mapping`. Plain-dict adapters hid a real publication bug; lifecycle adapters now use native SDK response objects and the application uses their supported `.get()` access. Exact history/reply checks use the actual message timestamp/version and recheck the local publication snapshot after the remote read. References: https://docs.slack.dev/reference/methods/conversations.history/ and https://docs.slack.dev/reference/methods/conversations.replies/.
- Actual concurrent `MERGE` calls produced two same-key outbox nodes and duplicate sends. Application identity invariants therefore require native `UNIQUE` constraints, not a presumed implicit MERGE transaction guarantee. Trusted seed operations install supporting indexes/constraints and wait for `OPERATIONAL`; runtime notification writers refuse a missing constraint and never fall back to admin credentials. A constrained concurrent loser may read back only the matching immutable persisted postcondition. Source inbox/request/record identities are constrained too. Reference: https://falkordb.github.io/docs-staging/commands/graph.constraint-create/.
- Notification root versions exclude `recorded_at`, because alert ingestion updates that delivery timestamp on retries. Outcome versions bind the current persisted approval/action. Version identity is included in the externally visible message, so a prior same-status receipt cannot reconcile a later version. Only documented `chat.postMessage` parameters are sent; no client-provided message ID is treated as an exactly-once guarantee. Reference: https://docs.slack.dev/reference/methods/chat.postMessage/.
- Transport state comes from the SDK's actual `is_connected()` result, not worker liveness. TaskGroup supervises the socket, durable inbox, notification consumer and the one file-locked SDK writer; a failed competing writer does not overwrite the active connector's state. Reconnect reconciliation is bounded to 4x15 top-level messages, with gaps/truncation explicit. Metadata-only edits retain the message's actual content version rather than the delivery timestamp. Reference: https://docs.slack.dev/reference/events/message/message_changed/.

## Correctness repair: proposal authority

- `agents.safety.validate_proposal` is the shared deterministic authority. It produces recursively immutable facts and a canonical stable-fact hash. Rationale, query latency and alert-delivery `recorded_at` are not approval identity.
- Real proposals require Acme, exact monitored incident/deployment and saved failed probes, healthy exporter, current failed monitoring, restricted-role AWS target/document refresh, current published/remote Slack evidence and a matching active watchdog with at least120 seconds remaining. Slack is evidence, never runbook authority. Real recovery remains globally disabled.
- Simulation retains bounded official `algo.SPpaths` candidates, then checks actual node/edge health, recomputed cost and compatible tenant-private exclusions. No eligible result within the first five candidates does not prove global impossibility. Trusted topology initialization creates known empty tenant memory graphs; a failed memory read is not an empty exclusion set.
- Approval identity uses an operational native uniqueness constraint and deterministic tenant/incident/evidence key. Initial facts/expiry are immutable; changed evidence requires another approval. Concurrent command claiming and post-presentation revalidation belong to the following execution gate and are not implied by this proposal cutover.
